# 微信表情包制作 SOP：静态与动态

版本：1.0｜2026-10-16
适用：新角色表情、已有素材加工、工作/生活分组扩充、微信投稿准备。
这是制作和验收流程，不是自动发布工具；平台最新要求须以实际上传页为准。

## 一、流程总览

共同入口：盘点素材与版本 → 确认角色规范 → 逐款设计卡 → 确认费用与生成授权。

- **静态**：生成或复用图片 → 背景/蒙版检查 → 裁切与统一占比 → 补透明画布 → 缩放PNG → 技术与视觉验收。
- **动态**：复用或生成视频 → 完整视频及关键帧验收 → 按动作选片段 → 抽帧与稳定背景处理 → 统一调色板 → 循环GIF → 压缩后重新验收。

共同出口：用户确认版本 → 多规格配套素材 → 离线预览/校验清单/ZIP → 核对版权与平台要求 → 上传草稿（仅通道可用时）→ 单独确认提交审核。

## 二、先确认，不先花积分

每次付费前必须确认：
- 静态还是动态；聊天使用还是商店投稿；已有几款、计划新增几款。
- 角色标准像、脸型、眼耳鼻、比例、材质、画风、配字风格。
- 每款动作、表情、背景、文案、文字出现时机、禁止动作。
- 外观参考、固定首帧、动作参考分别是什么；工具不支持视频动作参考时须说明。
- 模型、生成次数、输出规格、单价、总预算、失败扣费规则是否已知。
- 是否可以先免费复用已有视频或图片。

**明确同意后才调用生成接口。** 不合格先报告，不自动付费重试、不擅自换模型降画质。积分与价格记录查询时间，不把历史余额当实时值。本地转换、剪辑、调速、排版不扣生成积分。

## 四、静态制作

1. 纯裁切、缩放、压缩用 Pillow/ImageMagick；创意生图读取当前可用生图技能，完成费用确认。
2. 小样先确认角色，再按批准计划批量，逐款检查脸、手、文字与画风。
3. 原文件只读，阶段输出写入唯一新批次目录。
4. 已有透明图可按 alpha 包围框裁切；仅在需要去背景时分割。不能全图替换近白色，避免误伤白脸、白肚子。
5. 边缘连通背景法只是候选：浅色主体可能与背景连通，须保护蒙版并人工复查；复杂背景不盲套阈值。
6. 裁切后统一角色占比与基线，补透明方形画布、安全边距，高质量缩放。不要每张紧裁铺满造成比例不一致。
7. 草稿主图可用 240×240 PNG；最终投稿格式、体积按实际页面核对。
8. 在浅色、深色、棋盘格背景检查边缘、主体漏抠、文字、裁切和可读性。

## 五、动态制作

1. 优先复用已认可视频。免费剪辑无法修正手型/脸型时说明，不能白块盖字、合成假手或整图晃动冒充肢体动作。
2. 新生成先检查业务生成状态及实际视频，不把接口顶层成功当作作品成功；积分不足与审核失败分开处理。
3. 看完整视频和起始/峰值/末帧，确认动作轨迹、次数、手型、角色一致性、固定镜头、字幕、遮挡和闪白。
4. 每款单独选截取起点和时长，不统一截短片段而丢失峰值。完整保留批准的双推等动作。
5. 调速、定格、爱心等独立图层可本地处理；文字与耳朵/脸重叠无法安全分离时保留原版并报告限制。
6. ffmpeg 在独立目录抽帧，固定缩放/补画布，不逐帧紧裁引入抖动；背景处理须时间稳定。
7. 多帧采样建立统一调色板，预留透明索引，避免可见色索引冲突；比较抖动策略并检查色闪。
8. GIF 是二值透明，不承诺半透明毛边无损。默认循环 loop=0；disposal 与实际合成回放核对。
9. 帧时长按 GIF 的 10ms 单位处理；检查首尾衔接，不默认反播不可逆动作。
10. 内部保守交付目标：240×240、透明、循环、每张 **<500000 bytes**。这不是对最新微信规定的替代。
11. 压缩优先减少冗余停顿、非关键帧、优化颜色，最后再调整帧率；每轮重新看动作。不能用低帧率让连推动作消失。

## 六、技术验收与用户验收分开

| 技术校验 | 视觉验收 |
|---|---|
| 实际文件格式、尺寸、字节数 | 角色与标准像一致 |
| GIF 帧数、时长、循环 | 动作次数、轨迹与手型正确 |
| 逐帧合成尺寸与透明情况 | 无花屏、白块、残影、色闪、漏抠 |
| 文件 SHA256、打包一致性 | 文案正确、文字时机符合设计 |
| validation.json | 压缩后节奏仍完整，循环自然 |

“存在透明像素”不等于抠图合格；“技术通过”不等于用户已批准。

预览必须重新读取最终文件。HTML 内嵌 base64 每次重建，并核对与源文件一致；不能只改说明文字。预览不更新先查嵌入资源，不一概归咎缓存。

## 七、目录与版本

建议：
```
sources/             原件只读
design/              角色规范、设计卡
runs/<唯一批次>/     输入、生成结果、视频、帧、候选
approved/            仅用户明确批准版本
delivery/            明确选择的交付版本
preview/             实际交付预览
validation/          校验、哈希和清单
```

独立交付物放项目 artifacts/；内部脚本和运行素材不机械归入交付目录。

只新建批次，不删除同名固定目录；路径已存在则停止或换批次。新生成不自动替换旧版，被否版本不能混入投稿包；不按最新修改时间自动选定稿。

版本清单字段：编号、分组、源文件/hash、外观和动作参考、起止时间、fps、时长、调色板、费用、技术结果、用户批准状态、已知问题、交付目标。

ZIP 打包后复核文件数量、名称、hash与预览。数量不足列待补，不虚构作品。

## 八、投稿材料清单

以下是可先整理的草稿规格，最终以当前平台为准：

| 材料 | 草稿规格/注意事项 |
|---|---|
| 静态/动态主图 | 240×240 PNG/GIF |
| 对应缩略图 | 每款一张，120×120 PNG，编号一一对应 |
| 封面 | 240×240 |
| 聊天图标 | 50×50 |
| 专辑详情横幅 | 750×400，体积与背景另核验 |
| 专辑文字 | 名称、介绍、逐款表情名 |
| 作者资料 | 与表情专辑材料分开 |
| 赞赏资料 | 可选，按页面另核验图片及文案 |
| 权利资料 | 照片来源、授权、工具使用条款、声明 |

本次页面要求：作者照片640×640≤500KB、另图750×400≤80KB；版权署名≤10汉字、形象简介≤80汉字、赞赏引导语5～15汉字。**不要把本次要求当所有页面永久标准**。8/16/24款套数也需在实际投稿页确认。

照片由本人拍摄解决的是参考照片来源，不自动确定AI作品全部版权。确认肖像/未成年人监护授权、第三方字体角色商标及生成工具使用条款；不编登记号、不代签声明、不公开原照片或孩子隐私。

## 九、上传与发布边界

- 开网页、连接器开启、attached=true，均不等于已具备文件上传能力。
- 先验证有效页面快照、定位元素及正常文件选择，再承诺代上传。
- 登录扫码、实名、验证码由用户操作。
- 快照自身循环过期时有限排查并查官方帮助，不无限让用户发继续、切开关，不绕过控制接口或读取凭据。
- 不能操作则提供手工清单，明确未上传、未提交。
- 草稿上传和最终提交审核分开；提交前核对预览、版权及声明，取得明确确认。不保证审核通过。
