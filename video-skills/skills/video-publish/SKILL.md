# Video Publish Skill（视频交付后 · 发布物料）

把做好的视频，变成可以直接发布的一套物料：**两张封面（3:4 竖版 + 4:3 横版）+ 标题 + 描述 + 标签**，并整体发到飞书。这是 `video-pipeline` 出片之后的「交付后动作」。

## 触发方式

- 用户显式：「出封面」「生成标题/描述/标签」「做发布物料」「封面发飞书」「这期的封面和文案」
- 主 skill 调用：`video-pipeline` Step6 收尾后的可选收口

## 输入

1. `output_root`: 本期产物目录（含 `1_knowledge_base.json` / `2_outline.json` / `<topic>.mp4`）
2. `topic_slug`: 英文短标识（如 `EV`），用于封面组件/合成命名
3. `send`: 是否发飞书（**默认 false·2026-07 用户定：飞书只在用户明说"发飞书"时才发，绝不出片/出物料后自动发**）。未明说 → 只把封面 png + 发布物料.md 落本地，报告路径，停在这里等用户发话。
4. `series_ordered`: 该期是否按课程顺序（默认 false）。`false` 时封面**不写 DAY/第几天**（见下）
5. 渲染项目根：`~/code/remotion-rlhf-poc`

## 你要做的事

### Step 0：读核心内容（决定标题/描述/封面主视觉）

读 `1_knowledge_base.json` 与 `2_outline.json`，抓：

- `core_concept.one_sentence` / `analogy` / `why_care` → 副标题、描述的价值前置
- `key_quotes` / 金句 → 标题候选、封面金句条
- `knowledge_map` 顶层骨架 / `outline.title` → 主标题、描述的结构骨架
- 本片的**签名可视化**（分层图 / 飞轮 / 核心公式 / 管线图）→ 封面主视觉选型

### Step 1：写发布物料（**按平台分别产出 · 抖音 + 小红书**）

写到 `<output_root>/发布物料.md`。视频同时发**抖音**和**小红书**，两平台**标题字数 / 标签数不同、必须分别给**（字数与标签数是**硬约束，超了直接裁到合规**；标题字数含标点空格按字符数）：

**抖音**（信息流 · 强钩子 · 干练）

- **标题：≤30 字**，钩子式（实体比喻 / 悬念问句 / 痛点数字），1 条主推 + 2 条备选，每条都数够 ≤30
- **描述**：精炼 3-5 行——痛点开场 → 讲什么（分点、配 emoji）→ 一句收口；别长篇
- **标签：≤5 个**，槽位少更要精准——**至少 2-3 个紧扣本片具体内容的细分标签**（讲什么就标什么：记忆系统→#记忆系统 #上下文工程，智能体评测→#大模型评测 #Agent评测，RAG→#RAG #检索增强）+ 1-2 个大领域词引流（#AI #大模型 #程序员）。别 5 个全填大而空的领域词——那样搜本主题的人反而搜不到

**小红书**（笔记 · 亲和钩子 · 口语）

- **标题：≤20 字**，更口语更戳（如「AI 写代码总差一口气？这 5 个开源神器」需压到 ≤20 → 「AI 编程 5 个坑·开源神器解决」），1 主推 + 2 备选，每条数够 ≤20
- **描述**：精炼，emoji 分点、亲和口吻——痛点开场 → 要点（分点）→ 互动收口（邀评论）
- **标签：≤10 个**，大领域 + 细分内容 + 长尾混合，**槽位够，细分内容标签更要给足（≥半数紧扣本片讲的具体概念/工具/方法）**：先按本片核心知识点逐个起标签（记忆系统→#记忆系统 #AI记忆 #上下文工程 #Agent记忆；RAG→#RAG #检索增强 #向量数据库），再补领域词（#大模型 #AI #程序员）和泛长尾（#技术分享 #干货）。别让 10 个槽位全被大领域词和泛长尾占满

> **标签覆盖纪律（两平台通用·硬规则）**：大领域词（#AI #大模型 #程序员）只负责引流、不区分内容，**必须搭配紧扣本片实际讲了什么的细分标签**——从 KB 的 `knowledge_map`/`glossary`/`key_quotes` 和 outline 标题里抽核心概念、工具、方法逐个起标签。反例（真踩过）：做记忆系统的视频，标签里**一个记忆相关的词都没有**，全是 #AI #大模型 #技术分享 这类大而空的——这样系统识别不出主题、搜「记忆/上下文」的精准受众也找不到，不合理。**自检：把本片核心主题词逐个对照标签清单，确认每个都有对应细分标签覆盖，没覆盖就补上（先删泛长尾腾槽位）。**
>
> 自检：抖音标题逐条数 ≤30、小红书 ≤20；标签数抖音 ≤5、小红书 ≤10。**超限直接删 / 改短到合规再写入**，不要写超限的候选。描述整体偏精炼，别堆术语。

**遵循用户内容偏好**（见 memory `video-content-preferences`）：导向真实项目应用/学习，不走就业指导套路；讲清价值别只堆术语。

### Step 2：现写封面组件（bespoke，不套死模板）

> ⚠️ **默认设计语言 = 品牌层级流（2026-07 CC 舰队编排 ep01/ep02 踩坑后定死 · 优先级高于下方「白卡」建议 · 出封面前先读记忆 `video-publish-note`）**
> 踩过的坑：照下方「白卡当 hero」把签名图塞进一张大白卡、元素堆一团、系列名反而做小 → 用户判「一大块白框元素太多看不清 / Claude Code 怎么还这么小 / 元素优先级忘了」整张打回。**默认改走品牌层级流**（范例 `Cover_Fleet1.tsx` / `Cover_Fleet2.tsx`，与记忆 `video-publish-note` 信息层级铁律同源）：
> 1. **系列主题最大**——系列/品牌名（如 `Claude Code`）**超大白字、整张最显眼**、一眼可见养系列识别；不是小 chip、绝不能被本期词压过。
> 2. **本期主题词**——暖橙 `mono`、`⟩ 关键词 ⟨` 命令样式（如 `ultracode` / `worktree`），字号次于系列名。
> 3. **断言**——一句中字点题（做什么 + 好处）。
> 4. **主图 = 暗色精简的「可信内容可视化」，绝不塞进大白框**——用该片签名可视化的**暗色精简版**（fan-out 发光节点 / 隔离轨道 / 飞轮 / 公式），暖橙唯一强调、彩色发光边只用来区分语义；**别把一堆元素堆进一张白卡**（用户判「元素太多看不清」）。宁可少，缺口 > 堆叠。
> 5. **内容总结**——底部一行小灰字（真实战绩数字，别抢焦点）。
> 整组**垂直居中、大留白**；暖橙**唯一**强调色；英文专有术语首字母大写（命令关键字如 `ultracode`/`worktree` 保留小写但作暖橙主题词唱主角）。
> **白卡（下方高 CTR 第 1 条）不是默认**：仅当①用户明确要「论文 / 技术图」质感，或②系列本身走亮色底时才考虑，**且动手前先跟用户确认**。与本块冲突一律以本块为准。**忘了用户偏好就问，别自作主张套通用规范。**

仿 `src/scenes/bespoke/Cover_Fleet1.tsx` / `Cover_Fleet2.tsx`（品牌层级流·默认）或 `Cover_D3P.tsx` / `Cover_EV.tsx` 的**自适应模式**现写 `Cover_<Slug>.tsx`：

- `const { width, height } = useVideoConfig(); const portrait = height > width;` 一套组件出两个比例。
- **竖版 3:4**：chip → hero 大标题 → 主题句 → **中间签名主视觉** → 底部金句/战绩条，**整组垂直居中的一整块**（`justifyContent:'center'`）。⚠️ **禁用 `space-between` 把内容甩到顶/底两端**（见下「封面构图铁律」）。
- **横版 4:3**：左标题区 + 右签名主视觉（或整体正面居中 + 主视觉）。
- 画风走 `design/theme.ts` 的 `C/F/S` + `TechBackground`，study-dark 高级感；主视觉复用该片签名基元（如 `LayerStack` 分层图 / 飞轮 / `Formula`）。
- 标题区：chip（领域标签）+ 大标题（点题词，强调词用 `C.accent`）+ 副标题 + 金句条。
- **`series_ordered=false` 时封面不写 DAY/第几天**（chip 用「领域 · 主题」而非「DAY N」）。
- ⚠️ **复用视频基元到封面要走"裸渲/无固定偏移"模式（血泪坑）**：很多基元是给 1920×1080 视频写的、内部写死了 `position:absolute; top:220`（对准视频主舞台三分区）。直接塞进封面会被这个偏移**往下推、和标题对不齐**（横版并排尤其明显、竖版也会"太靠下"）。复用前确认该基元有 `bare`/`fill`/无偏移模式（如 `LayerStack` 的 `bare` prop），让它随父容器居中；没有就在封面里包一层抵消，或现写一个封面专用的简化版。
- **横竖都要抽帧核对"主视觉与标题对齐"**：横版左标题↔右主视觉的顶/中对齐，竖版主视觉别太靠下——这俩是封面最容易翻车的点。

#### 高 CTR 封面要点（已验证 · Transformer/EV 两片实战）

1. **签名架构图做成「白卡高对比」当 hero**（⚠️ **可选风格·非默认** — 默认走上方「品牌层级流」块的暗色签名主图；仅当用户要「论文/技术图」质感或亮色系列、且用前确认时才用此白卡路线）：把该片的脊柱/签名图（架构图 / 分层栈 / 公式 / 管线）放进一张**浅色/白色卡片**（`linear-gradient(180deg,#FAFAFC,#EEEFF3)` + 大阴影 `0 30px 90px rgba(0,0,0,.45)`），图内色块用 pastel 描边（`hue+'1A'` 底 + `hue` 边）。**别用 study-dark 的暗卡直接铺**——暗底暗图在缩略图里糊成一团、不"跳"；白卡像一张"真·论文/技术图"，可信感强、点击率高。study-dark 暗背景 + 白卡架构图的反差正是 Transformer 封面的命门。文字在白卡里用深色（label `#1B1B22`、sub `#5A5F6B`）。
2. **钩子式标题（别用平铺直叙的主题名）**：两条高 CTR 路线——①**实体比喻**（"拆开 AI 的发动机"、"给 Agent 盖一栋评测五层楼"）；②**悬念问句**（"掉分了，你定位到哪一层？"）。强调词 `C.accent`。平铺标题（"智能体评测体系化"）远不如这两类抓眼。
3. **一组件出两变体（A/B 备选给用户挑）**：组件加 `variant` 入参（如 `"A"|"B"`），用**不同钩子标题 + 同一张签名架构图**；变体 B 可**高亮签名图里与钩子呼应的那一块**（如问"定位到哪一层"就高亮"效果评估"层，视觉给答案）。每个变体各注册 Composition、用 `defaultProps={{ variant: "A" as const }}` 传参。一次产 2 设计 ×2 比例 = 4 张，让用户选设计 + 拿全比例。
4. **横版标题折行坑（必踩 · 必修）**：横版左列窄，大标题会把末尾词挤成孤行（"一栋"/"一层？"单独一行，很丑）。修法：标题每行 `whiteSpace:"nowrap"` + **横版字号显著小于竖版**（竖版 ~104→横版 ~58-72）+ 左列 `flex:"0 0 auto"`（随内容定宽、别用百分比）+ **收窄右侧白卡**（如 720→560）给标题让位。改完务必横版抽帧复核：标题不折、副标/金句不溢出、列宽+卡宽 ≤ 画布减 padding。
5. **专有英文术语首字母大写 · 系列主题词唱主角（必查 · 真实踩过）**：
   - **首字母大写硬规则**：所有专有英文术语/系列主题词在封面（chip / 大标题 / 副标题 / 白卡标题 / 金句条 / 文件名外的任何展示文本）一律**首字母大写**——`Skill`/`Skills`、`Agent`/`Agents`、`MCP`、`RAG`、`LoRA`、`KV`、`API`、`SDK`、`FC`、`LLM`、`Transformer`、`Attention`、`Embedding`。**写成小写就是 LLM 输出的视觉 tell**（看起来像随手敲的英文单词、不是"标题级专有名词"），会拉低高级感。文件名 `SKILL.md`/`AGENTS.md` 等约定全大写则保留原样。
   - **系列主题词必须唱主角**：本期主题词（如 Skill 集 → "Skill"、MCP 集 → "MCP"）在 hero 大标题里**字号 ≥ 同行其他词 × 1.15-1.4**、配 `C.accent` 强调色 + 同色 textShadow glow。**绝不能让主题词跟同行普通词等大、等色**——那样观众扫一眼根本看不出本集主题。竖版尤其要狠（可直接单独成行 +50% 字号）。
   - **顶部领域 chip 要清晰可读**：主题词所在的 chip（如 "智能体 · Skill 开发"）字号竖版 ≥ 32、横版 ≥ 28，`fontWeight: 800+`，带 `boxShadow: 0 0 28px ${C.accent}33` 让它在缩略图里跳出来。`letterSpacing: 4` 让英文术语透气、不挤在汉字里。**别把它当"次要标签"写小**——它是观众扫到的第一眼"这是讲什么的"信号。
   - **自检（渲完后必看缩略图）**：把封面 png 缩到 ~200px 宽（手机刷视频的视觉量级），问自己：①一眼能看出本集主题词是什么吗？②主题词是英文且首字母大写吗？③ chip 文字看得清吗？三个有一个不达标，就回组件改字号/大小写/突出色。
6. **封面构图铁律：中心不留空、垂直居中一整块（用户打回 · 别再犯）**：竖版（3:4）**绝不用 `justifyContent:'space-between'`** 把内容甩到顶/底两端——那会在**视觉中心留一大片空心**，读作"没做完的废图"（ep03 首版这么犯过、被用户直接打回）。正解：
   - **整组内容 `justifyContent:'center'` + 合理 gap 居中成一个 cohesive block**（chip / hero / 主题句 / 主视觉 / 战绩条一起居中），上下留成对称留白而非中间空洞。
   - **视觉中心必须有主视觉锚点**：白卡签名架构图，或一条**与本期主题呼应的签名小图**（如 headless/CI 期做一条静态 CI 传送带 `git push ▶ → claude -p 🤖 → JSON { } → 贴回 PR ✓`；管线/飞轮/公式同理）。**没有中心主视觉就别做封面**——空≠高级，中心空=废图。
   - **主题句要够大够明显**：大白话主题句（"做什么+好处"）竖版 fontSize **≥66**、强调行配 `C.accent` + glow，别被 hero 压成小字；观众要一眼读到本集在讲什么。
   - 横版本就正面居中，同样加主题小图强化，别只堆文字。
   - 自检：缩到 ~200px 看，中心是不是空的？主题句够不够大够清楚？空/小任一条不达标就回改。

注册 Composition 到 `src/Root.tsx`（横版 1440×1080 + 竖版 1080×1440，`durationInFrames=60`）；出两变体时各注册横竖共 4 个，用 `defaultProps` 传 `variant`：

```tsx
<Composition id="Cover<Slug>-Landscape" component={Cover<Slug>} durationInFrames={60} fps={FPS} width={1440} height={1080}/>
<Composition id="Cover<Slug>-Portrait"  component={Cover<Slug>} durationInFrames={60} fps={FPS} width={1080} height={1440}/>
// 两变体：再加 A/B 各横竖，defaultProps 传 variant
<Composition id="Cover<Slug>B-Portrait" component={Cover<Slug>} defaultProps={{ variant: "B" as const }} durationInFrames={60} fps={FPS} width={1080} height={1440}/>
```

参考实现：`src/scenes/bespoke/Cover_EV2.tsx`（白卡五层楼建筑剖面 + A建筑比喻/B定位钩子两变体，横竖自适应）。

### Step 3：渲两张封面 + 自检

```bash

npx remotion still src/index.ts "Cover<Slug>-Portrait"  out/cover/cover_3x4.png --frame=30
npx remotion still src/index.ts "Cover<Slug>-Landscape" out/cover/cover_4x3.png --frame=30
```

**多模态抽帧自查**：标题不折断行（横版窄列里大标题最易折，字号/列宽要调）、不溢出、主视觉清晰、金句不压边。有问题就改组件重渲。
归位到 `<output_root>/cover/封面_3x4_竖版.png`、`封面_4x3_横版.png`。

### Step 4：整体发飞书（**仅当用户明说"发飞书"·`send=true`**；否则跳过，只报本地物料路径）

1. **物料文档**（标题/描述/标签）：

```bash
python3 ~/.claude/skills/feishu-doc-write/scripts/write_doc_to_feishu.py \
  --md "<output_root>/发布物料.md" --title "<主标题> · 发布物料"
```

拿回 docx url。

2. **封面图片 + 一条文字**（标题 + 文档链接 + 标签）：

```bash
python3 ~/.claude/skills/video-publish/scripts/send_images.py \
  --text "📦 <主标题>\n完整标题/描述/标签 → <docx_url>\n标签：#... #...\n封面 3:4 / 4:3 ⬇️" \
  --images "<output_root>/cover/封面_3x4_竖版.png" "<output_root>/cover/封面_4x3_横版.png"
```

脚本复用 `feishu-video-send` 的凭证（`config.json` / openclaw claude 应用），走 `im/v1/images` 上传拿 `image_key` → 发 `msg_type=image`。

3. **成片 mp4（标准步骤，别漏）**：调 `feishu-video-send` 发 mp4——≤30MB 内联播放，>30MB 自动降级飞书云盘链接。这是「整体发送」的一部分，封面/文档/视频三样都要发到。

```bash
python3 ~/.claude/skills/feishu-video-send/scripts/send_to_feishu.py \
  --mp4 "<output_root>/<topic>.mp4" --caption "<主标题> · 成片"
```

把视频链接（`url`，drive 模式）一并放进上面第 2 步的文字消息里，让用户一条消息拿全。

### Step 5：报告

给用户：封面两张路径 + 物料 md 路径 + 飞书文档 url + 视频链接 + 已发的封面图片。**确认三样都发到了**（封面 / 物料文档 / 成片 mp4）。

## 注意

- 封面是**代码**（住在 remotion 项目里），物料 md 与封面 png 归位到 `<output_root>`。
- 标题/描述按用户内容偏好（见 memory `video-content-preferences`），不堆砌、不就业导向。

- 不要在这里重渲整片；这是出片**之后**的物料动作。
