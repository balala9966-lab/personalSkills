# Video Self-Evolve Skill

视频生产链路的**自进化器**。把这条链路里讲过的方法论（autoresearch：造一个贴着真目标的裁判 + 围栏 + 棘轮）反过来用到我们自己的生产流程上——用每期的**返工信号**当诚实的反馈，自我加固质检与规则，逐期逼近"用户第一次就满意"。

**核心定位：只进化"知识/评估层"，绝不碰生产代码。** 你产出的所有改动只影响**未来某期**的评估/lint/规则/记忆，对正在生产或已定稿的本期**零影响**。

## 为什么需要它（根因）

曾出现：content-eval 给 v1 打 pass、事实满分、各维度 9/10，用户却判"只讲了项目是什么、没指导思想、没效果经验、场景泛泛"而整体返工两轮。**我们给自己造的裁判量错了东西**（代理指标合格 ≠ 真目标达标，典型 Goodhart）。自进化的使命就是：每次被用户的"真裁判"否决，就把那条没拦住的缺口，永久焊进我们的"代理裁判"（rubric/lint/规则/记忆），下次自动拦。

## 触发（围栏·时机）

- **只在用户明确认可成片后触发**："可以了 / 定稿 / 满意 / 就这样 / 发布吧 / 反思总结一下"。
- **绝不在生产中途触发**，**绝不进 video-pipeline 的任何卡点**，**绝不自动跑**——它是出片**之后**的单独收口动作，避免边产边改导致本期产物漂移。
- 一次只复盘"刚定稿的这一期"。

## 铁律（围栏·改动边界 · 不可逾越）

### 白名单——只允许动这些"知识/评估层"文件（且 append-only / additive）

- `~/code/video-agent-pipeline/docs/quality_rubric.md`：**加**评估维度 / 补判定说明（不删既有维度、不改既有阈值除非修正明确错误并单列确认）。
- `~/code/video-agent-pipeline/tools/preflight_lint.py`：**补** `KNOWN_MISREAD` 词条 / 调建议阈值（纯 advisory，不阻塞渲染）。
- 各 `~/.claude/skills/<video-*>/SKILL.md` 的"规则 / 纪律 / 注意"段：**append** 新规则（不重写既有流程）。
- memory（`~/.claude/projects/.../memory/`）：写 feedback/project 记忆 + 更 MEMORY.md 索引。
- `~/code/video-agent-pipeline/output/_self_evolve/`：返工台账、changelog（本 skill 自己的产物目录）。

### 黑名单——绝不碰（任何渲染/成片依赖的生产代码）

`render_bespoke.py` 的渲染逻辑、`src/primitives/*`、`src/scenes/bespoke/*.tsx`、任何 `manifest.ts`、`src/design/theme.ts`、`src/primitives/beats.ts`、`tts_fixes.json` 的既有条目（可由用户在生产时改，本 skill 不动）、任何 timing/audio/mp4 产物。**碰这些 = 可能弄坏下一期甚至已定稿片的渲染，红线。**

### 其余纪律

- **additive 是常态、GC 是周期性收口，二者配套**：默认只加不改（每期把返工信号 append 进 rubric/记忆/SKILL），这是安全底盘；但纯追加会逐期膨胀、重点被噪声淹没（"沉默失效"加剧）。所以每攒几期或某载体明显臃肿时，跑一次 **Step 0.5 巡检合并（GC）** 把重复规则合并成 canonical、单期个例下沉冷存——additive 负责"不漏"，GC 负责"不糊"。要改既有行为=RISKY，走提案、不自动落（GC 属天然 RISKY，见 Step 0.5）。
- **可回滚**：每次自进化写一份 `output/_self_evolve/changelog_<date>.md`，记清改了哪个文件、加了什么、为什么，便于一键撤销。
- **风险分级，RISKY 必须用户逐条确认**（见下）。
- **grounded**：每条改进必须能指到本期一个具体返工事实（用户某句反馈 / 某次重写），不凭空加规则。

## 流程（把五件套用到自己身上）

### Step 0.5 · 巡检合并（周期性 GC · 不是每期都跑）

> **为什么**：additive 铁律让规则只增不减 → rubric/记忆/SKILL 逐期膨胀 → 验收 agent 和生产 agent 要背的规则越堆越多、重点被噪声淹没、该触发的规则反而找不到（"沉默失效"加剧）→ 质量不升反降。GC 是给追加机制配的**收口阀**：定期把重复的合并、把没复发的下沉、把矛盾的消歧，让载体保持"少而锋利"。

**触发条件（不是每期跑，防 churn）**——满足任一即跑一次 GC：

1. **某载体明显臃肿**：单个 rubric 维度 cell / 单个记忆文件 / 单个 SKILL 规则段 塞了同主题 ≥3 条重复表述，或多个维度职责重叠边界不清。
2. **每攒约 5 期自进化**：不管臃不臃肿，周期性回看一遍（呼应返工台账"攒够样本找系统性盲区"）。
3. **用户明确要求**。

**四个动作**：

- **同主题多规则 → 合并成一条 canonical**：留最锋利的一个例子/判据，删重复表述；多个维度职责重叠的，要么合并成一个、要么明确划分边界（每个维度一句话说清"我只管什么、和别的维度分界在哪"，重复判据归唯一 owner、其它引用它而非重复）。
- **单期个例从未复发 → 从热路径下沉到冷存**：只出现过一次、没再复发的具体个例，从 rubric/热记忆挪进 `output/_self_evolve/` 的 changelog/台账冷存——保留可追溯，但不再占验收 agent 的"视野预算"。（呼应"防过拟合到单期个例"。）
- **矛盾 → 消歧**：两条规则冲突时，明确写清"谁在什么条件下胜出"，不并列堆着让读者猜。
- **软上限兜底**：给关键载体定个软行数/条数上限（如单个 rubric 维度 cell、单条热记忆），超了就触发一次压缩。

**纪律（GC 是天然 RISKY——允许改既有内容，但每处必须）**：

1. **合并不丢能力**：自检——合并前每一条 load-bearing 规则/反例，在合并后的版本里仍被覆盖（只删重复表述、不删能力；踩坑例可精简但要留指针）。这是 GC 的头号红线：合并不是删。
2. **三同步不断链**（见 [[capability-sync-discipline]]）：改了 rubric 维度，同步检查引用它的生产 skill 规则段、preflight_lint 扫描、MEMORY.md 索引——一处改、关联处跟上，别留悬空引用。
3. **changelog + 可回滚**：写 `output/_self_evolve/changelog_<date>_GC.md`，逐条记"改了哪个文件 + 怎么合的 + 原文哪几条被并进来 + 怎么回滚"。
4. **大改列 RISKY 给用户逐条确认**：合并/删维度这类"较大或可能有争议"的改动单列成清单摆给用户拍板，别默默大改。

### Step 1 · 采集返工信号（评估 = 诚实的反馈）

从刚定稿这一期挖：

1. **用户 flag 了什么**：逐条列用户在本期提出的不满 / 修改要求（原话）。
2. **改了几轮、改了什么**：v1→v2→v3 各因什么返工（内容深度 / 可读性 / 结构 / 视觉…）。
3. **哪个阶段本该拦住**：每条 flag 对到一个生产阶段（retrieval / research / script / scene-design / render / 各 eval 卡点）。
4. **读 eval 报告对照**：本期 `eval/*.md` 里哪些维度给了高分，却正是用户否掉的点 → 这就是"代理裁判量错了"的铁证。

### Step 2 · 归因到"该哪个代理裁判拦住"（方向）

每条返工 → 映射到一个**可加固的载体**：

| 返工类型 | 加固载体 |
| --- | --- |
| 内容描述式 / 没 thesis / 没配方 / 场景泛泛 | quality_rubric 内容维度（actionability_recipe / guiding_thesis / scenario_specificity / payoff_frontloading） |
| 可视化看不出走向 / 没讲清概念 | quality_rubric 视觉维度（viz_communicates） |
| TTS 读符号 / 多音字 / 字幕一坨 | preflight_lint（KNOWN_MISREAD / 阈值 / 符号扫描） |
| 反复出现的生产手法/坑 | memory（feedback）+ 对应 SKILL.md 规则段 append |
| 既有维度存在但没拦住（权重/红线不够狠） | RISKY：提案调维度权重或 fail 红线 |

没有对应载体的 = 当前体系的盲区，记成缺口提案。

### Step 3 · 生成改进 + 风险分级（围栏）

- **SAFE（纯 additive，可直接落）**：新增 memory；quality_rubric **加**一个维度；preflight_lint **补**词条/符号；SKILL.md **append** 一条规则；写台账。
- **RISKY（必须用户逐条确认，绝不自动落）**：改既有 rubric 维度的判定/权重/红线；动 preflight_lint 既有阈值到会改变大量结果的程度；任何"看起来该改但沾生产代码"的想法（一律转成"建议用户在下次生产时手动处理"，本 skill 不碰）。

### Step 4 · 落 SAFE + 提案 RISKY（棘轮：留优、可退）

1. 落地所有 SAFE 改动（编辑白名单文件）。
2. 写 `output/_self_evolve/changelog_<date>.md`：逐条"改了哪个文件 + 加了什么 + 对应本期哪条返工 + 怎么撤销"。
3. RISKY 列成清单，**摆给用户逐条拍板**，不自动改。

### Step 5 · 更新返工台账 + 报告

1. **返工台账** `output/_self_evolve/rework_ledger.md` 追加一行：`日期 | 主题 | 返工轮数 | 根因维度 | 已加固载体`。这是"用返工次数当真目标信号"的累积载体——攒够样本周期性回看，找系统性盲区（如总在"可实践性"翻车 → 该维度升权重）。
2. 报告给用户：本期返工根因摘要 + 已落 SAFE 清单（带 changelog 路径）+ 待审 RISKY 清单 + 台账已追加。

## 兄弟能力（建议，非本 skill 自动做）

这些也是"自进化/可验证"方向，但插入点不同，列出供用户决定是否单独立项：

- **交付前"用户视角"批判**（最狠·解放用户的裁判位）：出片前派独立 agent 模拟用户验收尺子（thesis？可操作 how？场景尺子？干货前置？可视化讲清？），先自己否一遍再给用户。属 video-pipeline 渲后/交付前卡点，**不在本 skill**（本 skill 是事后复盘）。建议作为 RISKY 提案交用户决定是否加进 pipeline。
- **基元库自生长**：每期复现的 bespoke 可视提炼进共享基元（涉及生产代码=黑名单，本 skill 只"建议"不动手）。
- **已验证事实缓存 / 读音字典自增**：事实缓存可落 memory（SAFE）；读音进 preflight_lint（SAFE）。

## 注意

- 本 skill **不改任何被它复盘的产物**，也**不重渲**——纯知识/评估层进化。
- 改 SKILL.md/rubric 属"元层自我修改"，务必 append-only + changelog，避免把流程越改越乱（呼应 autoresearch 的"贪心棘轮会过拟合"：自进化也要防过拟合到单期个例——单期个例进 memory/台账即可，别轻易升成全局红线，攒够样本再升）。
- 与主线零耦合：video-pipeline / 各生产 skill **不引用**本 skill；它只在定稿后被用户或收口动作单独唤起。
