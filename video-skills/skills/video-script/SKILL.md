# Video Script Writer Skill

把结构化知识库变成可拍摄的视频大纲。

## 触发方式

- 用户显式：「/video-script <kb.json> [--type 学习]」、「按这个知识库写大纲」
- 主 skill 调用：`video-pipeline` 第二步

## 输入

1. `knowledge_base_path`: 知识库 JSON 路径（来自 video-research 的产物，**含 `series_context`** 系列定位事实）
2. `script_type`: `科普` | `故事` | `漫剧` | `学习` | `教程` | `开源速递` | `信息速递`
3. `output_path`: outline 写入路径（默认 `<同目录>/2_outline.json`）
4. `current_eval`: 可选。如果是「反馈回灌重写」模式，会附上一个 eval 结果，要按 issues 修正后重写

## 消费知识库的深度（学习/教程·关键）

知识库为深度做了准备，**这些深度必须流进 outline，不许丢**——丢了就回到"内容太简单"的老问题：

- `depth_layers[].derivation`（推导链）→ 落进 **L2 原理深潜段**的 narration/visual_anchor，把"为什么"讲透，而不是只报结论
- `depth_layers[].worked_example`（技术示例）→ 落进 **实战演示段**，对应 demo_code 和具体数字/shape/输出
- `depth_layers[].everyday_example`（日常案例）→ **「原理→示例」配对硬规则：每讲完一个原理，紧跟一句"举个你平时会遇到的例子：…"**，用观众有体感的日常场景印证刚讲的原理。可紧贴在该原理段 narration 末尾，或紧随其后单开一个极短"示例"小段。这是把抽象原理落地的关键，别讲完原理就干巴巴过去
- `reverse_explanations[]`（反向解释）→ 单独成一个"反向解释"小节，或融进 L3 应用段：用观众熟悉的现象反向印证原理（"你平时用的 X 之所以这样，正是今天的原理"）。注意与 everyday_example 方向相反：这条是"现象→原理"，上一条是"原理→举例"，两者都要有
- `core_concept` / `suggested_openings[].hook_sentence` → 提炼成**开头钩子**（前 3 秒抛核心冲突/悬念）和**金句**（口诀/比喻），分别落进 0-5% 钩子段和回顾段。**钩子=点题合一（硬规则）**：钩子首句在抛痛点/反常识的同时，把**本集主题词**当成那个"答案"点出来（如「为什么换个问法答案天差地别？秘密是今天的『注意力机制』」）——一句话既抓人又点题，不再单设一段干巴巴的主题陈述
- `series_context`（系列定位事实·**必须照用，禁止瞎编**）→ **旁白严禁念"Day 几/第 N 天/集序数字"**；系列衔接一律用**主题**承接（「上一集讲了注意力，这一集拆 Transformer 整个架构」），不报编号。`position_line` 改写成主题衔接句、压成半句紧跟钩子；`day` 仅供内部排序/路线图组件，**不进旁白**；`deps_learned` 落进开头"已学的快速回扣（不重讲，用主题名）"；`unlocks_next` 用主题落进**今天意义段/下篇预告**。`series_context:null` 时不写系列定位句。
- `learning_mainline`（学习主线）→ 不只决定讲述顺序，**还提示一张"内容脊柱图"**：主线的每一步 = 全片骨架图上的一个模块。outline 顶层标一个 `spine_diagram` 建议（按主题选形态：架构图/管线图/分层栈/推导链/循环图），并让**每个模块段的 `visual_anchor` 写明"在脊柱图上高亮本模块"**、回顾段写明"复用完整脊柱图作思维导图"。这是学习视频最有价值的连贯性结构——观众全程有"现在在整体哪个位置"的心智地图（脊柱图怎么落地由 video-scene-design 实现）。
- 若知识库这些字段为空或太薄 → 不要硬编，写进 `retrieval_requests.json` 触发补检

## 留人 / 完播 / 传播三件套（学习/教程·关键）

学习视频跳出率高、传播弱，根因是开头在念欢迎词、中段无悬念、结尾无互动。三件套硬规则：

1. **开头钩子前置 + 点题合一（降跳出）**：第一段必须是钩子，前 3 秒抛痛点/悬念/核心概念特写，narration **首句是问题或反常识陈述，且把本集主题词作为"答案"点出**（如「为什么大模型能听懂你的话？秘密藏在这个叫"注意力"的机制里」——既抓人又点题），`visual_anchor` 必须强视觉冲击（核心概念特写/动态特效）。系列定位压成半句、用主题承接（不报 Day 号）紧随其后，**绝不允许用"欢迎来到/这是第 N 天/今天我们来聊聊"开场，也不许在旁白里念集序数字**
2. **总-分-总结构（提完播）**：钩子后立刻用一句话抛出全片要回答的**核心问题（总）**，中间分点讲（L1/demo/L2/L3），结尾回顾呼应这个核心问题。中段（约 55%，demo→L2 过渡处）插一个**内容钩子**——提问/悬念再次抓注意力（如「你觉得注意力机制最难理解的是哪部分？」）
3. **金句 + 互动（提传播）**：≥1 条**金句**（把核心知识点提炼成易记口诀/比喻），编织进价值段与回顾段；结尾必须有**互动话题引导**，发起讨论（如「你还想了解大模型的哪些底层原理？评论区告诉我」）

## 知识可视化即讲解 + 签名可视化冷开场（学习/教程·关键·留人）

> 来源：用户基于点击/留存效率观察 +「知识可视化是最大亮点、别做成 PPT」+ 本系列 A2《MCP》实践（开篇 8s 先把"一条活的 MCP 连接"完整跑一遍再进正文）。两条原理写进每集 outline。详见 memory [[video-visualization-is-the-teaching]] [[video-viz-cold-open]]。

**原理一·知识可视化即讲解（最高原则·反 PPT）**——学习视频最大的亮点 = 用可视化把知识本身讲明白，不是配音念 + 静态卡片（那是 PPT、理解不如原理可视化直接）。落到 outline：

- 每个知识点的 `visual_anchor` 必须写出**"演因果/过程/变换"的动态画面**，不能是"展示 X 的卡片/标题"。判据：关掉声音只看画面动，能否看懂这段。
- 选一张**贯穿全片的签名可视化/脊柱图**（源自 `learning_mainline`，即 `spine_diagram`），全片有主画布、各段挂上去展开，别每段孤立画。
- **可视化承载深度、不是漂亮空动画**：把 KB 的 `derivation`/`worked_example`（真实数字/推导）画进可视化；深度与可视化都要，别用动画稀释内容。

**原理二·签名可视化冷开场（开头先完整播一次再进正文·留人）**——开篇**先把本片签名可视化/核心机制快速完整跑一遍**（~8-12s，只演不深讲），再进正文（原理→问题→方案→价值→效果……）。两个作用：① 第一时间让观众看到"我们的知识可视化"的价值、勾住人；② 给全片埋下主画布，正文是对它的展开细讲。

- 这段冷开场**就是钩子本身**（视觉钩子 = 点题合一）：画面跑一遍签名可视化的同时，旁白首句抛痛点/反常识并点出本集主题词——**不额外多占段**，并入开场预算（仍 ≤ 全片 10%、≤30s 进正文细讲）。
- 冷开场只**演一遍不拆解**（快、整、抓人）；正文里这张图**慢放、分模块高亮、逐步算给观众看**（scene-design 的三处锚定）。
- 落 outline：第一段 `description` 标注"签名可视化冷开场（teaser）"、`visual_anchor` 写明跑哪张签名图 + 跑多快；body 段复用同一张图细讲。
- 自检：① 选定了一张签名可视化、开篇先完整跑一遍了吗？② 冷开场 ≤12s 且并入钩子（没把开场撑过 10%）？③ 正文复用同一张图细讲（非另起炉灶）？④ 各知识点 `visual_anchor` 是"演变化"而非"摆静态卡"？

## 开场效率铁律（学习/教程·关键·降流失）

「钩子前置」只解决了第一段，**没解决"开场到第一个主题模块拖太久"**——这才是流失高发区。病根不是欢迎词（那是低级错误），而是**开场把每个维度各开一段、不合并**：钩子回报独立一段、核心问题独立一段、意义独立一段、路线路标又独立一段，每段 10-15s，加起来开场就 45-70s 才进正题。

**血泪对照**（同链路两个视频）：

- ❌ 反例「大模型评测」：开场 **46s / 4 段**——钩子(13s) + 钩子回报独立(11s) + 核心问题独立(15s) + 路线路标独立(7s)。每段都没欢迎词、都合规，但**段间没合并**，进主题慢、占比偏高。
- ✅ 正例「Transformer」：开场 **39s / 3 段**——钩子(13s) + **系列定位 ＋ 核心问题合并**(12s) + **意义 ＋ 金句 ＋ 三步预告合并**(14s)。三段三维度、秒进主题。

**硬规则**：

1. **钩子=点题合一**：点题不单设一段——钩子首句就把本集主题词作为"答案"点出（见三件套第 1 条）。后面不再有"核心问题独立一段"；要么省掉、要么作为钩子那段的第二句把主题展开成"全片要回答的那一个问题"。
2. **相邻维度尽量合并成一段**：系列定位（半句、主题承接、不报 Day 号）＋ 核心问题与钩子合一段；今天意义 ＋ 金句 ＋ 路线预告合一段（每段仍 ≤3 句）。**别让"系列定位/路线路标/意义"各占一个独立短段**。
3. **意义价值大幅瘦身**：开头只留**最狠的一句**（学不会会被卡在哪/解锁什么挑一个最戳的），其余两件事拆散编织进正文对应模块或结尾意义段，**绝不在开头堆"为什么核心+学不会后果+解锁什么"三件事**。
4. **开场段数 ≤2-3**（钩子&点题 + 合并意义&预告，系列定位并进任一段的半句），**开场总时长 ≤ 全片 10%**、目标在 **~30s 内进入第一个主题模块**（L1/第一个技术点）。
5. **路线路标不独立成段**：把"接下来 N 段讲什么"作为意义段的 **coda 末句**，而非单开一段。
6. 自检：列出开场每段 seq + duration + 维度，**若出现两个相邻短段（各 ≤15s）讲的是可合并维度 → 合并**；算"钩子首句 → 第一个主题模块首句"的秒数，>35s 或开场 >全片 10% 即返工压缩；**钩子首句若没点出主题词 → 返工**。
7. **钩子后带一句点赞关注（标准 CTA·快带·半句）**：钩子点题后、进系列定位/正题前，自然带一句"顺手点赞关注，方便学习"——**≤半句、口播顺、不单设独立段、不拖开场**（并进钩子段或系列定位段的尾巴，仍算进 ≤10% 开场预算）。与结尾的"互动引导+关注"不冲突（一头一尾各一次）。**简短快速，绝不展开成"求三连/记得分享给朋友"等啰嗦话术。**

## 全局硬约束（不分类型，违反即不合格）

1. **禁止废话开场**: 严禁「众所周知...」「随着科技的发展...」「在当今社会...」「今天我们来聊聊...」「相信大家都...」等套路
2. **旁白长度**: 每个段落的 narration 不超过 3 句话，确保口播自然
3. **视觉锚点**: 每个段落必须标注 visual_anchor —— 用具体语言描述该段对应的核心画面（不是抽象概念，必须是"可拍摄的"）
4. **概念解释规约**（强制·绝对禁止违反）: 任何新概念/专业术语/缩写，首次出现时必须用「先专业后通俗」两段式立刻解释清楚。例：
   - ✅「KL 散度是衡量两个概率分布差异的指标。就像两份菜谱有多不一样——食材完全相同就是 0，毫无重叠就是无穷大」
   - ❌「PPO（一种算法）开始训练」— 太敷衍
   - ❌ 假设观众已经懂"RLHF / PPO / Transformer / KL 散度 / 梯度"
   - ❌ 用更难的术语解释难术语
5. **情绪标注**: 每个段落标 `emotion_level`（1=平静 ~ 5=极度震撼/感动）
6. **具体性**: 不允许「很多/非常/大量」等模糊词，必须用具体数字或具象描述
7. **可视化要求**: visual_anchor 不能只写"展示公式 X"，必须写"如何动画化呈现这个公式的物理过程"

## 类型专属约束

> **硬步骤（学习/教程必做）：动笔前必须先 `Read references/type_constraints.md`**——下面只是一行索引，完整的 11 段时间轴 / 开场禁忌 / 收尾结构 / 视觉风格都在那份文件里。不读就写 = 必丢细节。

详见 `references/type_constraints.md`。简要：

- **科普**: 8 段比例分配（钩子 6% / 锚定 12% / L1 15% / L2 22% 最长 / L3 15% / L4 10% / 高潮 8% / 收尾 7%）；类比驱动；每 30 秒一个小恍然大悟
- **学习/教程**: 结构含**钩子前置（前3秒抛冲突·学习类优先用"签名可视化冷开场"=视觉钩子，见上「知识可视化即讲解 + 签名可视化冷开场」节）→ 点赞关注(半句·快带) → 系列定位(1句) → 核心问题(总) → 今天意义 → 学习目标 → L1 → 实战代码 → 中段钩子 → L2 → L3 → 核心回顾+金句 → 下篇引入 → 下篇预告 → 互动引导+关注**；必须含 5 行核心代码 + 3 个真实工程场景 + ≥1 金句 + 中段钩子 + 结尾互动；严禁"面试"措辞、严禁欢迎词开场；收尾必须引出下一篇 + 发起话题讨论
- **故事**: 三幕式（建立 25% / 对抗 50% / 解决 25%）；展示不告知；角色弧光
- **漫剧**: 快节奏场景切换 8-15s/场；视觉优先；强对比；夸张表现
- **开源速递**: 干货密度优先、弱钩子弱引导；切入 8% / 架构总览 25% / 技术亮点 45%（最长）/ 典型用法效果 15% / 收束 7%；架构图驱动；亮点讲因果；**不要**情绪钩子/中段钩子/结尾互动/金句/系列定位（`key_quotes`/`interaction_prompts` 非必填）；保留概念两段式解释 + 具体性
- **信息速递**（数据驱动的领域速递，首个实例=股市每周复盘）: 信息类传播、弱钩子；开场点题 8% / 行情速览 20% / 结构分化 15% / **排序归因 25%（最长）** / 展望多空情景 20% / 观察变量 7% / 免责 5%；**核心是反空话分析质量**——每个核心判断走**五步链**（数据锚点→对比参照→推理链→反向限定/证伪信号→定性结论），删万能空话，多空并陈，事实/观点分离（口播措辞+屏上【数据】/【研判】角标）；溯源=主因/次因/放大器排序，展望=双情景+观察变量不做单点预测；数据接口可复跑+留痕、拿不到不编。详见 type_constraints「信息速递类」+ 六层分析骨架

## 输出 schema

```json
{
  "title": "20 字内吸引人标题",
  "logline": "50 字内一句话梗概",
  "target_duration": 总秒数,
  "tone": "轻松|严肃|悬疑|热血|温情",
  "target_audience": "目标观众",
  "emotion_curve": [{"time": 0, "level": 1}, ...],
  "structure": [
    {
      "seq": 0,
      "type": "开场|展开|高潮|结尾",
      "description": "本段内容描述（第一段固定为钩子型开场；中段钩子/结尾互动在 description 标注）",
      "narration": "旁白，≤3 句",
      "duration": 秒数,
      "visual_anchor": "动画化的可视化描述（避免静态公式；开场段必须强视觉冲击=特写/动态特效）",
      "emotion_level": 1-5,
      "transition_from_previous": "承接方式"
    }
  ],
  "demo_code": "可选，如果是学习/教程类型且某段含代码，把 3-5 行核心代码字符串放这里",
  "key_quotes": [{"quote": "金句/口诀/比喻", "used_in_seq": 2}],
  "interaction_prompts": [{"type": "中段钩子|结尾话题", "text": "提问/讨论话题原文", "seq": 7}],
  "retrieval_requests": []
}
```

`key_quotes`（≥1）和 `interaction_prompts`（中段钩子 ≥1 + 结尾话题 ≥1）为**学习/教程类型必填**；其他类型可省。

### 补检循环（信息缺口回灌）

写脚本时如果发现知识库**缺关键信息**（缺案例支撑某论点、缺原理推导、缺可视化数据），除了在 outline 的 `retrieval_requests` 字段标注，**还要把缺口写进 `<同目录>/retrieval_requests.json`**（追加，结构 `{stage:"script", query, purpose, needed_for, blocking, priority}`；`needed_for` 写哪段/哪概念需要它，`blocking=true` 表示缺它故事断/推导缺环=必须补到）——这是主 pipeline 触发 video-retrieval 定向补检的契约文件。不要硬凑内容糊弄过去。

## 反馈回灌支持

如果输入含 `current_eval`：

1. 解析 eval 的 `issues` 数组（按 severity 排序：critical > high > medium > low）
2. 优先修复 critical/high
3. 每条 issue 都对应 outline 里某段的具体改动

## 自检清单（输出前必须确认）

通用：

- 每段都有 narration / visual_anchor / emotion_level / duration
- 总时长接近 target_duration
- 概念解释规约满足
- 无废话开场

学习类型专属：

- **动笔前是否 Read 了 `references/type_constraints.md`（不是只看一行简要）**
- **第一段是否为钩子（前 3 秒抛核心冲突/悬念，首句是问题或反常识，visual_anchor 强视觉冲击）**
- **是否禁用了"欢迎来到/这是第 N 天/今天我们来聊聊"等欢迎词开场，且旁白全程不念 Day 号/集序数字？**
- **钩子=点题合一：钩子首句是否在抓人的同时点出了本集主题词（没点到主题词即返工）？**
- **钩子后是否带了一句"点赞关注"标准 CTA（半句快带、并进钩子/系列定位段、不单设段不拖开场）？**
- **开场效率：开场 ≤2-3 段、点题并进钩子、意义只留最狠一句（其余拆散）、路线路标没独立成段？"钩子首句→第一个主题模块"≤35s 且开场 ≤全片 10%？（见「开场效率铁律」）**
- **系列衔接是否照用 KB.series_context、用主题承接（上集主题→本集主题），没瞎编也没念 Day 号？**
- 是否有系列衔接（半句、主题承接、紧跟钩子；不报编号）
- **钩子后是否有"核心问题（总）"一句话锚定全片，且结尾回顾呼应它**
- 是否有今天意义段（为什么今天的内容核心 + 不学的后果 + 解锁什么后续）
- 是否有学习目标预告段（3-5 条具体能力）
- 实战代码段是否标注了 demo_code（3-5 行核心）
- **是否有 ≥1 中段内容钩子（提问/悬念，写入 interaction_prompts）**
- **是否有 ≥1 金句（口诀/比喻，写入 key_quotes）**
- **每个原理段后面是否都紧跟了一个日常案例示例（"原理→示例"配对，能配的都配上）**
- 是否有至少 3 个真实工程场景（非"面试题"）
- 核心回顾段是思维导图式还是详细复述（必须是前者）
- 下一篇问题是否非哲学（必须）
- 下一篇预告是否明确给出题目（不能"下回分解"）
- **结尾是否有互动话题引导（发起讨论，写入 interaction_prompts）+ 关注系列引导**
